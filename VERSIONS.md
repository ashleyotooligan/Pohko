# Change your mind in ink

An opening event establishes version one and the original reason. An amendment includes a nonempty explanation and a complete replacement thesis. It increments the derived version number. The asset symbol cannot change through an amendment.

The append API returns a new journal and does not mutate the supplied object. Validation applies to the entire resulting history. Editing JSON outside the API changes a file; it is not an authenticated owner action merely because an importer can verify a rehashed history.

## Evidence reset

The current opening or amendment event marks the evidence boundary. Only evidence with a greater sequence number contributes to the current version. Earlier records remain inspectable in the ledger and source packet.

This boundary applies even when an amendment only changes narrative text. It deliberately asks for post-revision evidence instead of quietly inheriting a prior interpretation.

## Browser and API

The browser revision form preserves the condition definitions and changes the reason, with an explanation. The API accepts a full thesis, including new condition definitions. Import a verified journal for a version with a different condition set.

## Owner reviews and closure

An owner review adds a note; it does not change the reason or numerical state. A close event archives the file and rejects subsequent events for that thesis ID. Historical reviews before closure still see the earlier state. New research after closure should start a new file and link the earlier ID in its reason or note.
